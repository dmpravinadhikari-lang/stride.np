# Reference images

Everything in this folder is generated by `scripts/make-reference-art.mjs`:

```bash
node scripts/make-reference-art.mjs
```

**These are hand-drawn vector illustrations.** They are not photographs, not
model output, and not anyone else's work. Edit the generator, not the SVGs —
the files are overwritten on every run.

## Why drawings and not photographs

Three reasons, in order of how much they matter:

1. **Nothing here can be someone else's copyright.** Architectural renders found
   online are almost always a practice's own marketing material, frequently
   watermarked and often naming their client in the title block. Putting those
   on Shailakshya's site would be using a competitor's work to advertise
   Shailakshya — and in Kathmandu valley the people most likely to recognise
   the house are the customers being pitched to.
2. **The hero slider needs identical geometry.** `hero-before.svg` and
   `hero-after.svg` come from one `house()` call with two material treatments,
   so they register perfectly. Two photographs almost never do.
3. **An honest placeholder beats a convincing fake.** These read as drawings, so
   nobody mistakes one for a finished project or for what the generator
   actually returns.

They are Kathmandu-specific on purpose — flat roof, parapet, stainless water
tank, window grills, close neighbours, overhead wires, marigold at the wall —
the same details the prompts in `worker/styles/packs.ts` insist on.

## What's here

| File | Used by |
|---|---|
| `hero-before.svg` | Hero slider, left — unfinished cement |
| `hero-after.svg` | Hero slider, right — same house, restyled |
| `hero-after-night.svg` | Spare: the evening half of the day/night pair |
| `<pack-id>.svg` × 7 | Style card faces, one per pack |
| `interior-*.svg` × 4 | Phase 2 interiors; unused in Phase 1 |

## Replacing them with real photography

Style cards resolve `reference/<pack-id>.webp` first and fall back to the `.svg`,
then to a flat material swatch. **So dropping a `.webp` in beside the `.svg` is
the entire swap** — no code change, no rebuild of the component.

The hero is two constants at the top of `web/src/main.ts`.

When the real photos arrive:

- **Hero:** a real Shailakshya house, shot straight on, and the *same* house
  restyled — ideally run through the visualizer itself once Workers AI is on.
  Both frames from the identical camera position, or the slider will jump.
- **Style cards:** ~600×400, WebP, under 60 KB each. These load on 3G phone
  connections. Note these should show a *style*, not claim a specific project,
  so visualizer output is a legitimate source for them.
- **The catalogue:** the pre-generation script (Phase 2, SPEC §5.2) needs the
  company's actual house list. That has to be real Shailakshya work — it's what
  the cache keys on and what prospects are being shown.
